# 音频方案与来源记录

## 结论

项目采用“代码从零合成”的原创音频方案：不下载音乐、不截取现成歌曲、不使用第三方采样，也不运行带商业限制的生成模型权重。Codex 根据游戏的像素 RPG × 办证地狱方向设计音符、节奏、波形和触发位置，脚本确定性生成最终 MP3。

这条路径不能替代正式法律意见，但把素材链缩短为“本仓库脚本 → 本仓库音频”，比来源不明的 AI 音乐服务或免费素材站更容易审计。

## 为什么没有直接使用开源音乐模型

- Meta AudioCraft 的代码是 MIT，但官方 MusicGen 权重是 CC BY-NC 4.0，不适合作为准备上线产品的默认生产链：[AudioCraft License](https://github.com/facebookresearch/audiocraft#license)。
- Stable Audio Open 的模型卡说明训练素材来自 CC0、CC BY 或 CC Sampling+，但模型本身使用 Stability AI Community License；商业使用需要按其条款注册，年收入达到门槛后还需另行申请企业许可，且输出不提供不侵权保证：[模型卡](https://huggingface.co/stabilityai/stable-audio-open-1.0)、[社区许可](https://huggingface.co/stabilityai/stable-audio-open-1.0/blob/main/LICENSE.md)。
- 本项目的声音只需要短循环 chiptune 和 UI 提示音，程序合成已能满足体验，不值得引入模型下载、额外许可和训练集相似性风险。

## 运行行为

- 配乐只在玩家主动点击“开始”后播放，避免浏览器自动播放限制。
- Web 和微信小程序默认声音开启，但都提供常驻“声音 开 / 关”按钮；设置只保存在当前内存，不写本地存储。
- 页面切到后台时暂停，恢复前台后按用户原有选择继续。
- 微信端遵循系统静音开关，并允许与其他应用音频混播。
- BGM 播放音量为 `0.18`；SFX 按用途使用 `0.30–0.48`，避免提示音压过配乐。

## 资产与触发

| 文件 | 用途 | 触发点 |
| --- | --- | --- |
| `opc-office-loop.mp3` | 104 BPM、16 小节 A/B 双段循环配乐 | 开始后持续播放 |
| `start.mp3` | 上行启动琶音 | 开始游戏 |
| `confirm.mp3` | 确认双音 | 选择继续路线、确认成本 |
| `exit.mp3` | 下行退出音 | 选择离场路线 |
| `back.mp3` | 反向短扫频 | 返回、重选、重新开始 |
| `checkpoint.mp3` | 打印机 / 收银铃 | 像素版进入成本确认节点 |
| `survived.mp3` | 短胜利号角 | 完成全部 25 题 |

机器可读的字节数与 SHA-256 位于 `design/audio-asset-manifest.json`。Web 和小程序各保留一份完全相同的本地副本，运行时不发起外部音频请求。

## 重新生成

需要 Node.js 22 和 ffmpeg：

```bash
npm run generate:audio
```

脚本会在系统临时目录生成 WAV，编码完成后自动清理，只把 MP3 写入两个运行端目录。修改合成脚本并重新生成后，需要同步更新清单中的字节数与 SHA-256。

## 人工听感验收

1. 进入任意 Web 版本，确认首屏静音，点击“开始”后配乐和启动音出现。
2. 连续选择继续、返回、退出路线，确认提示音短、清楚且不会遮挡操作。
3. 在像素版走到 Q24 后继续，确认成本确认页出现独立铃声；完成 Q25 后出现胜利号角。
4. 切换“声音 关”，确认 BGM 与正在播放的 SFX 都立即停止；再次开启后只恢复 BGM。
5. 切换浏览器标签页或让小程序进入后台，确认音频暂停；回到前台后恢复。
