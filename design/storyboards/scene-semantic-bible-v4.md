# 像素版逐题语义与分镜合同 v4

> 状态：像素版重新出图的唯一语义真相源。
> 题目与选项真相源：`content/quiz-v2.json`。本文只解释中文语境和画法，不改写题库。
> 核心判断：先让人一眼看懂“正在做哪件现实事情、刚选了什么、留下什么结果”，再谈像素质感和幽默；酷感不得替代题意。

## 1. 本轮为什么全部重审

旧稿的根本问题不是精细度，而是把登录、银行开户、支付选择、记账、服务器等题目都画成了门、管线、舱体和发光机关。它们看起来属于同一个世界，却不能回答题目。

新版遵守六条硬规则：

1. `idle` 先呈现现实场所、现实对象和完整决策项；用户不看题目也能说出主题。
2. 每个普通选项都有自己的 `action / resolved`，不能多人共用一张“机器亮了”的完成图。
3. `action` 必须画出人与物的真实接触；`resolved` 必须留下账户、回执、模块、合同或其他可追踪结果。
4. `quit` 演该选项独有的中文笑点，不再统一坐地、抱头或红灯。
5. 金额、规格、品牌名、时间及状态由清晰的 DOM 像素标签承载；底图负责对象、动作、表情和空间。题意依赖品牌时允许出现识别标识，不再一刀切禁 Logo。
6. 同一主角、棕色背包、同一产品原型、公司资料夹与备案材料逐题传递。连续性来自遗留物，不来自把所有场景画成同一种科幻房间。

## 2. 选项级视觉合同

每题保留一个共享 `idle` 场景；选择后按 `optionId` 读取专属 outcome 资产或透明差异层：

```text
Question visual
├── base: desktop/mobile 四态母板，作为 idle 与 fallback
├── labels: 当前题准确的品牌、金额、规格和状态 DOM 图层
└── outcomes[optionId]
    ├── desktopAsset
    ├── mobileAsset
    ├── frame: action | resolved | quit
    └── labels: 该选择独有的结果状态
```

在专属资产未完成前，旧四态母板只可作为 fallback，不得被标为“已完成重画”。

## 3. Q01–Q09：从憧憬到公司账务

### Q01 是否真的上线

- 中文语义：不是问会不会写代码，而是愿不愿把 Vibe Coding 原型变成真实线上产品。
- idle：清晨共享工作室；电脑上是真实可交互原型，旁边是上线入口。主角看着自己的作品，眼睛亮、嘴角上扬。
- `launch`：开心前倾按下上线计划，原型接向公网；结果是“准备上线”，不是已经商业成功。
- `not-launching`：平静合上电脑，原型留在本地草稿盒。
- 必须可读：`上线 / GO LIVE`；禁止冷脸、疲惫脸、密室闸门充当主题。

### Q02 是否需要登录

- 中文语义：登录换取身份、留存和召回；免登录换取低摩擦，两条都是合理路线。
- idle：产品网页必须有真实登录 UI：手机号/邮箱框、验证码或密码框、登录按钮，同时有“游客进入/直接体验”。
- `login`：开启登录，用户成功登录、头像和留存回流点亮；主角有“增长黑客”式自信。
- `guest`：移除登录遮罩，用户一步直达核心功能；主角轻松，不是登录失败。
- 必须可读：`登录`、`游客进入`；门锁只能作辅件，不能替代界面。

### Q03 赚钱还是为爱发电

- 中文语义：`200 刀`是 Codex Pro/GPT 开发会员成本，不是产品售价或收入；赚钱路线想把订阅投入赚回来。
- idle：同一产品居中，一侧为付费用户/回本路线，另一侧为爱心免费路线；桌上清楚出现 Codex Pro/GPT 订阅账单。
- `profit`：把 `$200/月`账单钉上回本板，产品连向收款；主角斗志旺盛但尚未赚大钱。
- `love`：巨大爱心给产品供能，免费用户使用；主角满足，钱包在持续变瘪。
- 必须可读：`Codex Pro`或最终确认会员名、`$200/月`、美元符号和 GPT/OpenAI/Codex 识别标识。

### Q04 是否成立一人公司

- 中文语义：为了经营收款，是否把个人项目升级为需注册、维护并承担责任的公司主体。
- idle：彻底离开办公桌构图；主角站在“个人开发者”与“公司主体”分界，前方是公司设立服务大厅、营业执照轮廓、公司章和待解锁支付能力。
- `found-company`：迈过门槛、签一人公司方案、领取“公司筹备”资料夹；坚定且向往。
- `too-scared`：停笔，把未签方案退回，留在个人项目一侧。
- 必须可读：`公司设立`、`一人公司/企业主体`；豪华 CEO 办公室和四张办公椅都不等于公司成立。

### Q05 ¥500 公司注册代办

- 中文语义：真实动作是交 ¥500、准备材料并等待 1–2 天；“献祭 GPT Pro”是机会成本梗。
- idle：真实代办窗口、报价单、材料托盘、营业执照/公司章出口；允许把付款口画成“注册代办火炉”。
- `register`：把写有 `¥500 / GPT Pro` 的付款券丢进火炉，火焰吞钱，另一侧代办员盖章接单；结果吐出“已受理”资料夹和 1–2 天倒计时。主角悲壮肉疼又期待。
- `eat-instead`：收回钱，开心奔向热饭，不再瘫在机器旁。
- 必须可读：`公司注册代办`、`¥500`、`1–2天`、`GPT Pro`。

### Q06 租真实工位还是地址挂靠

- 中文语义：注册需要地址材料；比较“能真实办公的工位”和“只提供合规地址证明的挂靠”。
- idle：同框两套现实方案。工位侧必须有桌、椅、电脑、电源、门牌、租赁合同；挂靠侧必须有地址证明、协议、集中信箱/门牌墙，且没有实际工位。
- `desk`：试坐、插电脑、签工位租约；门牌和租约进入公司资料夹，主角 All in 地兴奋。
- `hosted`：保留打工工牌，在线签挂靠协议，收到地址证明和信箱编号；务实松气。
- `too-much`：两份合同都不签，抱回资料离开。
- 必须可读：`工位 ¥1500/月（约 ¥1.8万/年）`、`地址挂靠 ¥2000/年`。

### Q07 开设银行对公账户

- 中文语义：是企业银行账户申请，不是开锁、开门或金库冒险。
- idle：真实银行企业业务柜台；营业执照、地址证明、公章、开户申请表、柜员、企业网银 UKey 和回单位必须出现。
- `open-bank-account`：递材料、签企业结算账户申请并支付年费；GPT Pro 筹码只作肉疼辅梗；结果拿到“对公账户已开立”回执和 UKey。
- `stop-before-bank`：动态累计金额令主角瞳孔地震，收回未提交材料；不是账户被冻结。
- 必须可读：`企业开户/对公账户`、`¥500/年`、动态 `已花 ¥X`。

### Q08 选择支付方式

- 中文语义：在商户配置页选择微信支付、支付宝或两者都接；重点是勾选和启用，不是两条隧道。
- idle：像真实收银台配置页的支付方式卡片墙。微信和支付宝是当前可操作卡，银行卡/云闪付等可作为灰色未开放背景卡，形成“很多方式里做选择”；旁边有手机收银台预览。
- `wechat-pay`：仅微信卡打勾和启用，手机只出现微信支付。
- `alipay`：仅支付宝卡启用，微信保持灰色。
- `both`：双手同时勾选，两张卡与手机双按钮都启用；费用只对微信认证计入。
- `run-away`：取消申请，所有卡仍未启用，主角抱资料跑路。
- 必须可读：`微信支付`、`支付宝`、`认证 ¥300/年`、`无认证费`、`交易费按量`，并使用相应识别标识。

### Q09 代理记账还是自己做

- 中文语义：公司没赚钱也要记账、申报并保持公私财产分离；是财务公司/会计工作，不是泛流水线。
- idle：代理记账公司服务台、财务人员、发票凭证、财务软件、申报日历；中央明确分开公司账户/账本与个人/家庭钱包。
- `agency-bookkeeping`：把资料、发票和流水交给会计，签年服务合同；会计持续做账申报，主角每月仍对接。
- `self-bookkeeping`：自己录票、对账、申报并把公司卡与个人卡分盒；留下 `约4h/月`，主角认真熬夜。
- `buy-sneakers`：合同未签，账本仍待申报；主角抱新球鞋盒开心离开。
- 必须可读：`代理记账 ¥2,000/年`、`公司账`、`个人账`、`每月申报`、`约4h/月`。

## 4. Q10–Q17：开发工具、产品技术与备案

### Q10 选择写代码用的 AI

- 中文语义：选择 Coding AI 订阅，不是产品运行时模型；免费工具也继续开发。
- idle：真实开发桌、代码编辑器和四张同级订阅卡：GPT、GLM、Kimi Code、免费工具。主角前倾、眼睛发亮，像第一次认真做产品。
- `gpt-ultra`：刷美元订阅，代码补全飞快，钱包瘪；兴奋中肉疼。
- `glm-pro`：确认连续包年，拿到年度订阅票据；理性满意。
- `kimi-code`：打开月度订阅和代码助手侧栏；轻松笃定。
- `free-tools`：倒出空钱包，把开源/免费工具箱搬上桌；穷但倔强，不离场。
- 必须可读：`GPT $200/月`、`GLM Pro 连续包年 ¥1,430.4/年`、`Kimi Code ¥200/月`、`FREE/免费工具`及各自识别标识。

### Q11 产品本身是否使用 AI

- 中文语义：Q10 是开发者写代码的 AI；本题问最终用户是否在产品运行时调用 AI。
- idle：主视觉是真实产品功能原型；左后方 Coding AI 小徽标只留在开发笔记本，前方产品有明确 `AI 功能`待定模块。
- `no-runtime-ai`：`AI 功能 OFF`，普通表单/搜索/规则仍绿色跑通，Token 计价器和合同夹撤下；主角清醒轻松。
- `runtime-ai`：用户在产品中直接对话/生成，`AI 功能 ON`；Token 计数、内容审核、企业认证和供应商合同开始工作；主角期待又盯账单。
- `goodbye`：关闭的是产品运行时 AI/产品，不是拔掉 Coding AI；向 Token 账单告辞。
- 必须可读：`AI 功能 ON/OFF`、`TOKEN 按量`、`企业认证`、`供应商合同`、`内容审核`。

### Q12 域名、SSL 与 DNS

- 中文语义：最新题库的 Q12 是把本地产品变成可安全访问的网址；服务器规格在 Q14。
- idle：浏览器地址栏仍是 `localhost`，旁边是真实域名购物车、打开的 SSL 锁、DNS 解析表；禁止服务器机柜抢主题。
- `buy-domain-stack`：付款后地址栏变为 HTTPS 示例域名，锁合上，`A/CNAME`连向产品；主角故作轻松地小得意。
- `hotpot`：购物车未付款、产品仍在 localhost，主角真开心地端牛肉火锅。
- 必须可读：`DOMAIN/域名`、`SSL`、`DNS`、`localhost → https://…`、`A/CNAME`、`¥300`。

### Q13 短信验证码登录

- 中文语义：仅前面选择登录才出现；决定是否购买手机号验证码服务，或拆掉登录与商业化。
- idle：真实手机号登录页、`+86`、手机号和验证码输入框、发送验证码按钮、短信套餐卡、用户手机。
- `sms-login`：购买 1000 条，手机收到六位验证码并登录成功。
- `remove-login-and-commerce`：像网页积木一样拆下登录和支付模块，未支付预算划掉但无现金回流，产品改为游客直达。
- `quit`：验证码通知淹没手机，主角抓狂合上电脑。
- 必须可读：`1000条 ¥45`、`登录成功`、`游客直达/无需登录`。

### Q14 选择云服务器规格

- 中文语义：产品运行环境在 1核2G、2核4G 与放弃买四件衣服之间取舍；低配仍能继续。
- idle：真实云服务器购买页或两台规格明确的主机，主角拿部署包比较性能和预算。
- `one-core-two-gb`：小服务器 CPU/RAM 接近 100%，页面能开但等待，OpenClaw 小爪卡队列；主角皱眉。
- `two-core-four-gb`：基础规格在线、负载居中；肉疼但安心。
- `buy-clothes`：订单关闭、产品未部署；主角抱四件不同颜色 T 恤真开心。
- 必须可读：`1核/2G`、`2核/4G`、`¥1300/年`、`CPU/RAM`、`4 × ¥300`、`OpenClaw`。

### Q15 系统盘与数据盘

- 中文语义：选择系统/数据分盘，或只用 40G 系统盘并承担备份待办；数据盘不等于备份。
- idle：Q14 同一服务器打开前面板；`SYS 40G` 已在位，`DATA 100G` 候选槽为空，应用与数据文件等待放置。
- `system-and-data-disk`：系统文件与产品数据分别进入两块盘，结构清楚但不冒充已备份。
- `system-disk-only`：所有内容挤在 SYS 40G，空盘位保留，容量偏紧并出现 `备份方案？`。
- 必须可读：`SYS 40G`、`DATA 100G`、`¥600/年`、`¥200/年`、`备份方案？`。

### Q16 购买 3M 公网带宽

- 中文语义：让服务器真正可被用户访问；3M 是基础窄带，不是极速光纤。
- idle：同一服务器和 Q13 用户手机之间尚未接通；窄网线/带宽表为 0，主角拿套餐单疲惫叹气。
- `three-megabit`：接上线，表稳定在 3M，手机终于打开产品但略有排队。
- `quit-after-spending`：前面票据堆和动态已花金额击中主角，手停在最后插头前，用户手机仍离线。
- 必须可读：`3M/3 Mbps`、`¥724.2/年`、运行时动态 `已花 ¥X`。

### Q17 工信部 ICP 备案

- 中文语义：技术准备完成后提交网站备案材料，并承担 7 天游戏口径的阻塞等待。
- idle：真实工信部/ICP 备案风格表单，桌上有公司证件、域名/证书和服务器接入资料；产品为“待备案”。
- `submit-miit-filing`：逐项上传、按提交、状态审核中、七格日历翻过，得到通过回执；主角等到疲惫后真实松气。
- `quit-at-filing`：手悬提交按钮又缩回，带包离开已经准备好的材料。
- 必须可读：`工信部`、`ICP备案`、`提交`、`审核中`、`预计7天`、`通过`；不能提前出现公安备案。

## 5. Q18–Q21：四个顺承合规步骤

### Q18 公安联网备案

- idle：日常网安办事窗口、网站拓扑、身份核验、Q17 工信回执和第二组空七日历；主角“嘴角还没放下就愣住”。
- `submit-police-filing`：上传拓扑和身份材料，再等七天，材料夹新增第二份回执；无奈坚持。
- `quit-at-police-filing`：接起“妈妈”电话，抱回未递交材料退出排队；工信回执仍保留。
- 必须可读：`公安联网备案`、`再等7天`、工信已通过与公安新状态。

### Q19 经营范围与百万门槛

- idle：经营范围咨询桌有三个现实样板：自己的产品/服务、自行发布内容、多个第三方主体的平台；双备案材料夹在旁。
- `self-operated`：只有自己的产品交易链，第三方入口封住。
- `self-published`：只有自己向外发布，别人投稿槽锁住。
- `all-in-capital`：摆入多个第三方摊位，豪气立起“注册资本门槛”厚文件；可短暂撒钱，但落进门槛栏而非已支付。
- `quit-license`：钱包只剩百元意象，抱材料倒退。
- 必须可读：三种模式名；`注册资本门槛 ¥1,000,000`、`未支付/不计入已花现金`、其他成本 `待确认`。

### Q20 公众表达与安全评估

- idle：真实产品旁列发帖、评论、公开分享、社群四类功能卡；普通登录锁单独放，明确“仅登录不等于自动触发”。
- `no-public-expression`：功能卡收进未启用抽屉，产品仍可登录使用，记录当前未触发。
- `self-assessment`：逐卡放进风险矩阵，自己做清单、截图和材料；留下厚自评待办与 24h。
- `third-party-assessment`：顾问接清单、递回砖头般厚的报价信封；只进待确认报价，不付款。
- `quit-assessment`：被功能清单和报价砖压垮，再打“妈妈”电话离开。
- 必须可读：四种功能名、`当前未触发`、`自行评估 +24h`、`第三方询价 ¥12,000（待确认）`。

### Q21 等保定级压力预算

- 中文语义：依据真实资产、数据、支付和网络边界做待定级研判；5万/10万只是压力预算，不是官方必然结论或已付款。
- idle：安全咨询桌放服务器、数据盘、支付接口、网络拓扑和资产清单；两套方案夹均标未确认。
- `level-two`：只把数据模块放进研判沙盘，生成二级压力预算文件进入待确认架。
- `level-three`：支付线与数据一起进入沙盘，增加一层防护工作，生成三级压力预算文件；不更华丽、不加分。
- `quit-mlps`：抱着最初简单网站原型和“爸爸钱包”离开复杂材料桌。
- 必须可读：`待定级研判`、`二级压力预算 ¥50,000`/`三级压力预算 ¥100,000`、`待确认/未支付`。

## 6. Q22–Q25：终于回到产品和增长

### Q22 用户、场景、需求与竞品

- idle：回到 Q1 工作室，合规纸山压住产品；真实四栏白板分别放用户画像、场景照片、需求痛点和竞品截图。
- `clear-enough`：四类卡连起来但留一张问号便签；谨慎而非胜利。
- `big-company-risk`：大厂阴影压来，主角圈出窄场景和差异化，留下 12h 待办后继续。
- `not-thought-through`：四栏几乎空，主角拿访谈提纲和录音笔准备调研，留下 24h/约4天待办。
- `no-value`：取下最后需求卡、产品归盒，难过但清醒离开。
- 必须可读：`用户`、`场景`、`需求`、`竞品/替代`及两类待办。

### Q23 用户规模假设

- 中文语义：选择预测情景，不是已经获得这些用户；四档同分，越大不越成功。
- idle：产品测试/容量预测区，四张同样式数字卡和半透明预测人群；Q22 定位板保留。
- 四个 option 分别让预测区扩展为 100、1,000、10,000、100,000 的容量层；人数越大，压力和运营复杂度增加，但庆祝强度相同。
- 必须可读：四个数字和 `预计用户数/用户规模假设`。

### Q24 每用户月费

- idle：真实定价台左边是动态已花账本，中间三张同级价格卡，右边是 Q23 预计用户数和公式；咖啡/修图只是消费锚点。
- `price-9-9`、`price-19-9`、`price-29-9`分别挂对应月费牌并计算理论流水，不因价格高而庆祝更多。
- `cannot-charge`：反复写擦后价格槽留空，把筹码倒回咖啡杯，挫败但清醒离开。
- 必须可读：动态 `已花 ¥X`、三个每用户月费、`预计用户数 × 月费 = 理论月流水`、`不等于利润`。

### Q25 第一百个用户从哪里来

- idle：Q1 同一工作室变成黎明上线战情室；自然流台有三脚架/补光灯/内容脚本/社群，广告台有后台/CAC滑块，直接上线台有发布总闸和空用户席。
- `organic`：主角一人当 KOL、客服和运营，内容/社群/口碑汇向首批用户；强撑营业笑，留下 `+40h/月`。
- `paid-acquisition`：先设 CAC 上限再投入有限预算，手守暂停键；预算仍待设定，不直接扣固定金额。
- `launch-now`：自然流和广告台都关闭，打哈欠压下发布闸；产品上线、用户数可为 0，疲惫释然而非失败。
- 必须可读：三种获客方式、`持续工时 +40h/月`、`CAC上限`、`营销预算待设定`、`今天上线`。

## 7. 首批重画验收顺序

1. 先完成 Q01–Q04 的桌面 idle 与每个选项结果小样，验证人物表情、真实界面、品牌标识和公司主体门槛。
2. 通过后完成 Q05–Q09，重点盲测火炉付款、工位/挂靠、对公开户、支付多选、财务公司。
3. 再完成 Q10–Q12，重点盲测 Coding AI、产品运行时 AI、域名三件套。
4. 首批通过后才继续 Q13–Q25，不再一次性生产 50 张后统一返工。

1. 不看题目，5 秒内能否说出正在决定什么？

3. 选项后是否看得出刚选了哪一项？
4. 金额属于已花、待报价、压力预算还是注册资本门槛？
5. 能否找到至少一个从上一题带来的物件？
