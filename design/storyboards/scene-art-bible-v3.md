# 像素版场景美术圣经 v3：25 题连续叙事生产合同（已废弃）

> 状态：已被 `scene-semantic-bible-v4.md` 替代。v3 错误地先建立统一机械隐喻，再把题意套进去；其中“禁用品牌标识”“一题共用 resolved”等约束不再有效。
> 适用范围：仅像素版 `/pixel/`；不约束 minimal、paper、cyber 等其他视觉版本。
> 题目真相源：`content/quiz-v2.json`。题干、选项与费用不在本文件内改写。
> 旧资产用途：`scenes-v2` 仅作为构图问题样本与局部隐喻参考，不直接视为 v3 合格成品。

## 1. 一句话方向

把 25 题拍成同一个独立开发者带着“产品核心盒”跑完立项、开公司、开发、合规和上线的连续像素短片：**现实办事与工作场景占 70%，机械隐喻占 30%**；每次选择必须让一个具体物件发生可见、可追溯的变化。

不是 25 个互不相干的科幻密室，也不是“主角站着—摸一下机器—机器亮灯—退出时坐地”的换皮合集。

## 2. 当前资产审计与重做等级

### 2.1 关系等级

| 等级 | 定义 | 当前题目 |
|---|---|---|
| A：核心隐喻基本对题 | 不看题目也大致能猜到装置含义，但仍缺现实锚点、前后遗留物或具体动作因果 | Q03、Q08、Q10、Q11、Q12、Q14、Q16、Q19、Q20、Q21、Q24、Q25 |
| B：局部有关 | 有门、盾、桌、柜等相关元素，但题目主体不够明确，容易被理解成泛科幻关卡 | Q02、Q04、Q05、Q07、Q17、Q18、Q22 |
| C：题意辨识弱 | 隐去题目后很难识别真实决策，或核心实体与题目主要矛盾不一致 | Q01、Q06、Q09、Q13、Q15、Q23 |

### 2.2 重做等级

| 等级 | 处理方式 | 本轮适用 |
|---|---|---|
| R0 | 原图可直接使用 | 无 |
| R1 | 保留背景和人物，只修局部道具、颜色或像素噪点 | 无；所有现图都缺少完整连续性 |
| R2 | 保留核心隐喻想法，按五章连续空间重新构图并重画四态 | 所有 A、B 级题目 |
| R3 | 放弃现构图，从真实题意和笑点重新搭景 | 所有 C 级题目 |

R2 不是“往旧图上贴一个道具”。它仍要重新解决人物比例、镜头、产品核心盒、上一题遗留物、四态因果和移动端构图，只允许继承旧图的一个优秀核心想法。

## 3. 不可违反的统一资产合同

### 3.1 输出结构

| 项目 | 桌面 | 手机 |
|---|---:|---:|
| 四态母板 | 1536 × 1024，2 × 2；单格 768 × 512 | 1024 × 1536，2 × 2；单格 512 × 768 |
| 四态位置 | 左上 `idle`、右上 `action`、左下 `resolved`、右下 `quit` | 同桌面 |
| 图片格式 | 无损工作稿 PNG；交付 WebP | 无损工作稿 PNG；交付 WebP |
| option modifier | 与单格同尺寸的透明 PNG/WebP；只画差异道具、路线状态或粒子，不复制背景 | 独立重排，不可直接缩放桌面 modifier |

建议分层：`背景连续空间 → 固定家具 → 产品核心盒 → 人物 → 当前题核心实体 → option modifier → 光影/粒子`。母板承担四种基础因果，选项差异由 modifier 承担。

### 3.2 统一主角

- 唯一主角沿用人物母版：乱黑发、米白卷袖衬衫、深蓝牛仔裤、黑鞋、棕色双肩包。
- 肩带和背包不能在帧间消失、换边或改变大小；背包是贯穿 25 题的“一个人扛全部”的身份标志。
- 桌面人物高度控制在单格高度的 20%～25%，约 104～128 px；手机人物高度 21%～27%，约 160～208 px。不得继续使用难以辨认表情和手部动作的小人比例。
- 主角默认 3/4 右视；只有真实操作要求才转身。相邻题入帧、出帧的朝向与站位必须接得上。
- 表演原则：动作由物体驱动。看账单时眼睛落到账单；递材料时手和材料相连；拔线时线缆被拉紧；退出时带走或放下具体道具。

### 3.3 统一镜头

- 桌面：等效 35 mm 的轻广角、平视略俯 8°～12°、固定 3/4 横向视角；地平线在单格上方约 36%。
- 手机：同一机位语言的竖构图重排，不是横图裁中间；人物与核心实体必须同时完整可见。
- 当前题核心实体占画面有效面积 20%～34%；产品核心盒占 6%～10%；上一题遗留物占 3%～8%，只能辅助，不抢焦点。
- 同章题目通过横移 1～2 个工位、推镜或转角连接；跨章才允许明显转场。禁止每题重新进入一个全新的圆形大厅。
- 环境材质以真实木桌、金属柜、纸张、线缆、玻璃窗口、塑料终端为主；能在真实办公室找到的物体优先。

### 3.4 产品核心盒

产品核心盒是 25 题共同的视觉主语，不是普通行李箱。

| 属性 | 固定定义 |
|---|---|
| 外形 | 横向哑黑金属飞行箱，圆角护边；左侧提手，正面单个琥珀色卡扣，四角青色铆钉，顶部有一块无字米白标签窗 |
| 尺寸 | 桌面约 92 × 62 px；手机约 136 × 92 px；各帧不得忽大忽小 |
| 初始状态 | Q01 封闭、未接线 |
| 中段状态 | 逐步挂上登录模块、支付线、模型芯片、域名锁、计算/存储/带宽线和备案封条；只显示真实选择过的模块 |
| 最终状态 | Q22 重新开箱变为产品演示台；Q25 接上发布总闸，成为结果页主背景的中心装置 |
| 路线表现 | 为爱发电路线保留心形电池、不出现公司证照；无登录路线使用封口盖；无运行时 AI 路线留空 API 槽，不伪装成已接入 |

每张图至少出现核心盒本体或它的明确局部；如果因镜头靠近无法显示全箱，必须显示固定琥珀卡扣和青色铆钉作为身份锚点。

### 3.5 五章连续空间

| 章节 | 题号 | 现实空间 70% | 机械隐喻 30% | 连续方式与出章物 |
|---|---|---|---|---|
| 真要上线吗 | Q01～Q04 | 清晨的共享工作室：工作台、白板、小会议桌、打印机 | 产品盒启动轨、登录插槽、收费/爱心双能源、四岗转椅 | 镜头从工作台向右移动到会议桌；Q04 后主角把产品盒推上折叠小车 |
| 一人公司入场券 | Q05～Q09 | 同一政务服务中心及相邻银行、财税服务区 | 印章压机、地址样板抽屉、支付双线、双账本分拣 | 窗口号码灯和地砖保持一致；公司文件夹、地址牌、U 盾、支付线依次留在小车上 |
| 代码与云端账单 | Q10～Q16 | 夜间开发工作室连接小型机房：电脑、路由器、机柜、硬盘托架 | 模型芯片、Token 表、域名锁、带宽压力表 | 从开发桌沿电缆走到机柜；已经完成的模块始终低亮留在产品盒上 |

| 紫色 `#8F68C9` | AI、Token、按量模型能力 | Q10、Q11 的芯片与计量脉冲 | 扩散到备案和财税场景 |

### 3.7 顶部反馈预留带

- HUD 下方、场景和题卡上方固定保留进度栏；进度栏永久只承载“第 N / 25 题”和进度条，选择前后结构与文案职责不变。
- 选择反馈属于舞台直属的 DOM/UI 安全层，水平居中并贴近舞台底部，矩形必须完整包含在场景容器内；**不画进场景母板**，也不得回填到进度栏。
- 现金/固定成本：琥珀币片或收据从选择方向滑入对应 HUD 列；工时：小沙漏翻转；等待天数：旧纸日历片横向排开；Token/按量成本：紫色脉冲；待办：米白文件夹入列。
- 精确金额、小时、天数只由 DOM 文本显示，场景图与 modifier 不烘焙数字。
- “路线已重算”弹窗取消。选择确认只在舞台安全层短暂显示，约 720 ms 后进入下一题；返回重选只更新题目与账本。
- Q05、Q07 的“献祭一个月 GPT Pro 5x”需要专属反馈：精确品牌名只出现在舞台安全层 DOM 文案，图片内不出现平台 Logo；现金、时间和关键路径变化由顶部对应账本格短暂闪烁反馈。
- Q19 的土豪撒钱只能作为舞台内的克制粒子反馈，语义是“注册资本门槛已记录”，不得落到“已支付”列，也不得覆盖整屏。

## 4. 四态因果合同

| 状态 | 必须回答的问题 | 画面要求 |
|---|---|---|
| `idle` | 眼前具体卡在哪里？ | 画出未插的线、未盖的章、未分开的账本、空座位等可验证障碍；主角目光指向障碍 |
| `action` | 主角现在具体做了什么？ | 手、脚、工具与目标物发生接触；物体有位移、形变或被递交，不能只是人物靠近机器 |
| `resolved` | 这个选择留下了什么不可逆或可追踪的结果？ | 插头已扣住、回执回到手里、文件被分开、模块安装进核心盒；上一题遗留物继续存在 |
| `quit` | 他为什么退出，退出时带走/放下了什么？ | 优先演出该题退出选项的笑点道具和具体撤退动作；无退出选项时才使用备用“合箱离开”帧 |

以下动作全局禁用：

1. `idle` 只是站在画面左边看一个圆门。
2. `action` 只是伸手摸机器，装置没有可辨识的物理变化。
3. `resolved` 只是同一机器变亮、加光圈或放烟花。
4. `quit` 一律坐地、抱头或倒在同一角落。
5. 用巨型传送门、圆形祭坛、抽象能量管线替代真实的银行、备案、短信、账本或服务器实体。
6. 四格里人物、背包、核心盒、家具无因果地换位置或镜像。

## 6. option modifier 技术约束

| 类型 | 用途 | 生命周期 | 示例 |
|---|---|---|---|
| `route` | 表示用户真实选择并影响后题 | 从选择后持续到结果页；返回重选必须移除旧路线层 | 登录模块、爱心电池、支付线、存储盘、用户密度 |
| `persist` | 上一题留下的文件或装置状态 | 至少保留到下一题；关键物件可跨章保留 | 公司夹、U 盾、域名锁、备案封条、价格筹码 |
| `fx` | 现金、工时、天数、Token、待办、待报价等短反馈 | 只在舞台安全层或对应 HUD 格运行；`prefers-reduced-motion` 时隐藏动画并直接显示最终状态 | `cash-fx`、`seven-day-fx`、`pending-quote-fx` |
| `density` | 大量重复人物/座椅等可变规模 | 可按设备选择低/中/高密度图层；不改变分数暗示 | Q23 四档用户层 |

- modifier 必须带透明背景、与对应单格像素网格对齐；禁止用 CSS 模糊、3D 变换或矢量图破坏像素边缘。
- 同一 modifier 在 `idle/action/resolved/quit` 中如位置不同，应分别导出帧，不可让静态贴图穿过人物手臂或家具。
- 路线 modifier 的显隐以 `{questionId, optionId}` 历史重放结果为准，不根据题号猜测。
- 选择越贵、用户越多、服务器越大，不获得更华丽的场景庆祝；只展示物理差异。
- 金额、题号、按钮、平台 Logo、伪文字均不得进入图片。真实文案和数字由 DOM 负责。

## 9. 验收门槛

| 验收项 | 通过标准 |
|---|---|
| 题意盲测 | 隐去题目和按钮，5 秒内能从核心实体说出至少 20/25 题的决策主题；Q01、Q06、Q09、Q13、Q15、Q23 必须全部可辨识 |
| 连续性 | 任意相邻两题可找到主角、核心盒和至少一个上一题遗留物；同章地砖、墙体、主光方向不跳变 |
| 四态因果 | 每题 `action` 有物理接触，`resolved` 有结果物，`quit` 有题目专属退出行为；禁止仅变亮 |
| 路线正确 | 登录/游客、商业/为爱发电、运行时 AI/无 AI、不同支付/存储/用户/价格路线的 modifier 可正确出现并在返回重选后回滚 |
| HUD 与选择反馈 | 进度栏永久只含题目进度；钱、工时和等待变化由对应 HUD 格反馈，选择卡完整位于舞台安全层；无“路线已重算”弹窗，无场景遮挡 |

| 像素一致 | 无混入 3D 渲染、平滑矢量、摄影材质或高斯模糊；光晕边缘保持像素分级 |
