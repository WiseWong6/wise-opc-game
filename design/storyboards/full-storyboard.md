# 《一人公司生存模拟器》像素 RPG 完整分镜规范 v1

> **已废弃的场景合同（2026-07-16）：** 本文件只保留旧人物动作与画风参考，不能再用于确定题数、场景数、路线或运行时映射。当前唯一场景合同是 `scene-briefs-v2.md`，当前资产清单是 `scene-manifest-v2.json`。

## 1. 文档用途与生产前置

本文件是人物、动作、场景图的统一生产说明，可直接拆给生图 worker。它只定义视觉内容与分镜，不包含网页 UI、题目文案或运行时代码。

生产顺序必须是：

1. 先批准 `design/characters/founder/character-brief.md` 对应的人物设定板。
2. 再用同一获批人物母版生产表情表和动作条。
3. 动作条通过身份一致性、基线和尺寸检查后，才进入本文件的 15 组场景：intro、12 关、quit、spectate、victory。
4. 每组场景先生成一张含 4 个连续关键帧的连贯分镜板，审核通过后再分别生成/导出背景层、人物层、配角层和特效层；禁止从不同批次拼一个动作。
5. 每次场景生成都必须附上获批人物母版、对应动作条和上一关已批准场景作为风格参照。人物母版的身份权威高于场景草图。

若人物母版尚未批准，所有场景视觉任务保持阻塞；不得用当前网页里的 CSS 方块人代替母版继续生产。

## 2. 全局视觉合同

### 2.1 角色身份锁

- 主角始终是约 30 岁的东亚男性一人公司创始人：凌乱不对称黑色短发、米白卷袖衬衫、深蓝长裤、黑色便鞋、磨损棕色大背包/斜挎包。
- 默认是面向屏幕右侧的 3/4 办事姿态；眼神先动，随后是头颈和上半身轻微跟随。不得通过整个人物旋转、拉伸或非整数缩放伪造动作。
- 主精灵遵循人物母版的逻辑像素、左上光源、脚底基线、头身比、背包尺寸、肩带连接点和有限色阶。桌面、手机只做整数倍最近邻放大。
- 表情必须依靠眉眼、嘴形、下巴和头部角度，不使用浮动问号、汗滴、感叹号或表情符号。
- 场景中的人物尺寸变化不得超过获批默认立姿可见面积的 5%；躺倒、透视遮挡等特殊姿态改用头、肩、髋、膝、脚底等刚性锚点检查。

### 2.2 场景风格与镜头语言

- 成年像素 RPG 气质，压抑的公共办事空间与克制黑色幽默并存；不是大头萌宠、卡通贴纸或写实厚涂。
- 主色：煤黑 `#070b0f`、蓝灰墙 `#27343f`、旧纸米色 `#d8c9ad`、柜台深蓝 `#1d5fa8`、印章红 `#b8322b`；通过每关独立的重点色和光源变化区分地点。
- 透视统一为轻俯视 3/4 RPG 视角，地面基准线不漂移；镜头可以缓慢推近、横移或轻震，但不得倾斜整个世界。
- 前景用于制造遮挡和深度，中景必须承载主角与核心交互，后景必须清楚说明这一关为何是不同地点。
- 不把 12 关做成同一注册大厅换道具。每关的建筑结构、柜台轮廓、主要光源、核心机械/设施和配角职业轮廓至少有三项不同。

### 2.3 分层与文件建议

每个场景至少保留以下可独立导出的像素层：

- `BG`：墙体、门窗、天花、远景，不含人物。
- `MID`：柜台、机器、桌椅和本关核心装置。
- `FG`：前景遮挡物、近处文件、栏杆、线缆或人群肩部。
- `NPC`：柜员和配角；同一职业的循环动作整条生成。
- `HERO`：只包含获批主角与其固定背包。
- `FX`：灯闪、纸张移动、印章冲击、尘粒或环境光；不得烘焙到人物精灵。

本版运行时采用一关一张 `2 × 2` 四镜头母板，整板约 `1536 × 1024`，单格约 3:2。文件固定为 `web/public/assets/pixel/storyboards/stage-00.webp` 至 `stage-12.webp`；网页以 `background-size: 200% 200%` 精确显示单格，不拆散或混用不同批次的帧。人物动作条仍按人物母版的逻辑像素生产，再在场景中整数倍放大。

四格顺序是运行时合同：

- 左上：`idle`，进入本关后的建立镜头和可决策静止帧。
- 右上：`action`，递交、付款、核对、操作等本关独有办理动作。
- 左下：`pass`，接受后的身体反应与场景反馈；接受序列先显示右上，再切左下。
- 右下：`quit`，在当前地点退出后的倒地、离开或失落结果帧。

`stage-00` 是例外：四格对应入口分镜 `T0 → T1 → T2 → T3`，首次进入时按步进动画播放，减少动画模式直接显示右下最终定格。手机与桌面共用安全构图母板，场景窗保持约 `1.55:1`，完整显示单格而不做暴力裁切；若未来另做竖屏艺术重排，必须保持同一四格语义和人物锚点，不能替换现有身份源。

### 2.4 UI 与可访问性边界

- 生成图中不得出现任何汉字、英文字母、阿拉伯数字、可读印章、Logo、水印、按钮、HUD、进度条、票据金额、对话框或气泡。
- 场景可保留空白牌匾、无字文件、无刻度仪表、纯色指示灯和无字章面，所有可读信息由 DOM 覆盖。
- 顶部账本 HUD、左上进度条、右侧/下方题目卡均属于网页 UI，不进入场景图。
- 主角、决定性动作和关键道具不得落在左上进度覆盖区：母图 `x=0–34% / y=0–20%`。
- 减少动画模式直接显示每组第 4 帧；第 4 帧必须在无运动上下文时也能独立读懂。

### 2.5 通用裁切安全区

- **桌面场景窗（约 1.55–1.65:1）**：关键叙事安全区为母图 `x=6–94% / y=8–92%`；主角全身和交互点尽量在 `x=16–72% / y=24–90%`。左右各 6%、上下各 8% 只能放可损失背景。
- **手机场景窗（约 1.45–1.58:1）**：必须生成同构重排版；安全区为 `x=7–93% / y=10–92%`，主角全身在 `x=14–68% / y=25–91%`，柜员/核心装置在 `x=45–91% / y=23–82%`。
- **进度遮挡**：两端均避开左上 `x=0–34% / y=0–20%`；此处只放墙面纹理、管线或无关暗部。
- **外沿容错**：任何头发、背包、手、脚、文件和机械活动件距最终裁切边至少 24 物理像素；前景装饰可以出框，但不得与人物轮廓粘连。

## 3. SC-00 Intro｜办事大厅入口

- **场景地点**：一座巨大、年代不明的综合办事大厅入口；旋转门后是一眼望不到头的柜台长廊，尽头只有一束冷白光。
- **叙事目标**：第一眼说明“一个人背着全部岗位进入制度迷宫”，同时保留尚未作答前的犹豫和一点点不服输。
- **镜头与构图**：中远景建立镜头。主角位于左下三分之一，背对观众 3/4 朝右；大厅门框构成套框，柜台长廊形成强透视线指向右后方。右侧留出一个没有人物的目标空间，暗示即将前进。
- **主角动作表情**：轻微含胸，左手抓肩带，右手捏着一张完全无字的空白申请纸；先仰望大厅，再短促吸气，眉眼由警惕转为克制坚定。
- **柜员或配角**：远处三名只读轮廓的办事员分别整理纸、抬头、按铃；不与主角建立直接接触。队伍中有两三个疲惫背影，不能遮住主角发型和背包。
- **前景 / 中景 / 后景道具**：前景是半开的金属栏杆和磨损地砖；中景是主角、取号机、空白告示架；后景是连续窗口、栏杆、堆纸、吊灯和尽头冷光。
- **4 个时间节拍**：`T0 0ms` 门尚未完全打开，主角停在门槛外；`T1 350ms` 门向内滑开，冷光扫过鞋尖和背包；`T2 800ms` 主角跨入一步并抬头，远处办事员同步抬眼；`T3 1400ms` 主角站稳、收紧肩带，定格为可点击开始的默认画面。
- **可复用层**：大厅外框、地砖透视、远处柜台长廊、通用排队背影、主角 `enter-hall` 动作条。
- **必须独立生成内容**：入口巨门、取号机轮廓、纵深长廊灯光、门开启形成的冷光带；不得从注册关直接抠柜台替代。
- **无文字 UI 约束**：取号机屏幕全黑，牌匾和告示架为空白；不出现“开始”“A001”或关卡数字。
- **移动与桌面裁切安全区**：桌面主角中心放 `x=30% / y=68%`，门内长廊落在 `x=55–88%`；手机重排时主角移至 `x=28% / y=70%`，门框加高，长廊缩到右上，头顶留至少 18% 空墙给进度覆盖。

## 4. SC-01 第 1 关｜多岗分流台（动机）

- **场景地点**：大厅内的“多岗分流台”，一个柜员被四组不同形态的工作台包围：产品模型、电话耳麦、计算器账本、打包纸箱。
- **叙事目标**：把“产品、销售、客服、财务都写在你名字后面”变成一眼可读的空间压力，但不在图中写岗位名。
- **镜头与构图**：中景，主角左、柜员右，四条传送槽从右侧柜台扇形指向主角，形成视觉包围；镜头略微推近主角上半身与背包。
- **主角动作表情**：右手原本只接一张纸，随后发现四个托盘同时滑来；眉头先扬起再压低，嘴角收紧，肩膀被视觉重量压下一格，最后仍把空白纸夹在臂弯。
- **柜员或配角**：一名动作极其熟练的分流员，四只手不出现；用旋转椅和左右快速转身表达同时派活。后方四个剪影分别打电话、敲键盘、拨算盘、封纸箱。
- **前景 / 中景 / 后景道具**：前景为一只占画面角落的空纸箱；中景为四个滑槽、主角、柜员；后景为四个颜色不同但无字的工作隔间和成排未接电话。
- **4 个时间节拍**：`T0` 主角只面对中央一个空托盘；`T1` 左右两组滑槽亮灯并推出电话与账本；`T2` 另两组推出产品模型与纸箱，主角微微后仰；`T3` 四组道具在主角面前停住，他咬紧牙、收住后仰，形成“继续还是退出”的静止困境。
- **可复用层**：主角 `receive-overload` 动作、通用柜员转身循环、地砖与栏杆、纸张滑动 FX。
- **必须独立生成内容**：四路扇形分流柜、四类岗位道具组合、后景四隔间；此布局只属于第 1 关。
- **无文字 UI 约束**：隔间灯箱仅用四种颜色区分，不画岗位图标、字母或数字；电话和账本没有可读界面。
- **移动与桌面裁切安全区**：桌面主角 `x=31%`、托盘汇合点 `x=48%`、柜员 `x=70%`；手机重排把四路滑槽改为上下两层，主角保持 `x=30–38%`，不可因收窄裁掉任一类岗位道具。

## 5. SC-02 第 2 关｜注册专窗（公司注册）

- **场景地点**：低矮铁窗后的公司注册专窗，柜台中心是一台过分巨大的红色机械印章，旁边堆着整齐的新档案袋。
- **叙事目标**：让约 200 元成为“正式开始的入场券”，表现交钱前那一瞬间的肉疼和仪式感。
- **镜头与构图**：双人对峙式中近景。主角在左下，柜员居中偏后，巨型印章在右侧前景形成第三个视觉点；一条空白缴费托盘连接主角和柜员。
- **主角动作表情**：左手压住背包，右手打开磨损的钱包但尚未取出任何带数字的钱；眉毛内收、眼睛盯着托盘，嘴角呈克制的“肉疼”。
- **柜员或配角**：注册柜员戴旧式袖套，面无表情地把空白档案袋推到窗口下；手指停在印章扳杆上，等待决定。
- **前景 / 中景 / 后景道具**：前景是印章底座和散开的无字收据；中景是托盘、钱包、窗口；后景是铁栏、档案抽屉、刚装订好的新档案袋。
- **4 个时间节拍**：`T0` 柜员把空白档案袋推到窗口；`T1` 印章上方红灯亮起，托盘滑到主角面前；`T2` 主角打开钱包并短暂闭眼，手停在钱包内；`T3` 他重新睁眼看向柜员，手仍悬停，没有替用户提前完成支付。
- **可复用层**：注册窗口铁栏、主角 `wallet-hesitate`、柜员 `slide-folder`、红灯闪烁 FX。
- **必须独立生成内容**：巨型红章机械、注册档案抽屉、缴费托盘、袖套柜员；不能直接复用通用大厅窗口。
- **无文字 UI 约束**：钞票、档案、收据和章面均无字无数字；金额只由网页题目和 HUD 表达。
- **移动与桌面裁切安全区**：桌面主角 `x=27%`、钱包 `x=38%`、窗口交互点 `x=53%`、印章 `x=79%`；手机把印章缩到右下 `x=78%`，钱包与托盘必须仍在 `x=26–58%` 可见。

## 6. SC-03 第 3 关｜地址迷宫（注册地址）

- **场景地点**：办事大厅突然展开成一座室内微缩城市迷宫；柜台上有不同材质的建筑模型、空白地图和两只颜色不同的档案夹。
- **叙事目标**：说明注册地址、实际经营地、挂靠方案和风险不是一个地址框，而是一组会改变路径的选择。
- **镜头与构图**：轻俯视全景。主角站在迷宫入口左下，地址顾问在右上高台；白色与暗红两条路线分叉后绕向不同建筑模型，路径最终都通往半掩的检查门。
- **主角动作表情**：摊开空白地图，视线在两条路线间来回；眉眼警惕、头颈跟随路线移动，背包始终压在同一侧，脚没有提前踏入任何路线。
- **柜员或配角**：地址顾问用长尺依次指向两条路线；远处一名检查员拿着空白夹板，在门后只露出半身，制造风险感。
- **前景 / 中景 / 后景道具**：前景是近处屋顶与路障；中景是主角、分叉线、地图；后景是建筑模型、检查门、叠放的白色和暗红档案夹。
- **4 个时间节拍**：`T0` 桌面还是一张平地图；`T1` 建筑模型从桌面升起，两条路线亮起；`T2` 主角的头和目光从白路转向红路，顾问的尺子同步转向；`T3` 检查门在远处缓慢开一条缝，主角停在分岔前形成决策帧。
- **可复用层**：主角 `read-map`、顾问 `point-route`、检查员剪影、路线亮起 FX。
- **必须独立生成内容**：可升降微缩城市、双路线迷宫、两类建筑模型、检查门；不能只换墙上告示。
- **无文字 UI 约束**：地图没有地名，道路无箭头文字，文件夹无“白本/红本”字样；仅以材质和颜色区别。
- **移动与桌面裁切安全区**：桌面迷宫完整占 `x=12–92% / y=26–89%`，主角 `x=27%`；手机重排为纵向蛇形迷宫，主角位于下方 `x=30%`，顾问与检查门上移，两个路线终点都必须在安全区内。

## 7. SC-04 第 4 关｜财税档案室（记账与申报）

- **场景地点**：堆满年度账本的财税档案室，机械日历、算盘和报表传送带不断运作，即使收入抽屉是空的。
- **叙事目标**：表达“没赚钱也要持续维护”，让重复、周期性和永不停机成为主要压力。
- **镜头与构图**：横向流水线构图。主角位于画面中央偏左，身后是空钱箱，面前是持续送来空白账页的传送带；柜员位于右侧高柜台，背景账本架形成重复格栅。
- **主角动作表情**：一手翻空钱箱、一手接住新账页；先困惑确认箱内确实为空，再疲惫地把账页摊平，眼下增加一档阴影但不改变面部结构。
- **柜员或配角**：严谨的账务员一边拨算盘一边推动机械日历；后方两名档案员把相同厚度的账本逐层归档。
- **前景 / 中景 / 后景道具**：前景是被裁切的大算盘珠；中景是空钱箱、传送带、主角；后景是高耸账本架、机械日历、落灰吊扇。
- **4 个时间节拍**：`T0` 主角掀开空钱箱；`T1` 传送带送来第一叠空白账页；`T2` 机械日历翻过一页，背景又多一摞账本；`T3` 主角把账页压平并揉一下眉心，流水线仍在移动。
- **可复用层**：主角 `check-empty-box` 与 `rub-brow`、账务员算盘循环、纸张传送 FX。
- **必须独立生成内容**：账务流水线、机械日历、高耸档案架、空钱箱；第 4 关必须从空间结构上区别于注册窗口。

## 17. TR-Quit｜退出 / 成绩锁定动作链

- **场景地点**：退出发生在哪一关，就留在哪一关；当前设施继续运作，但其光线和环境声逐步退到背景。不能统一传送到“注册处门口”。

## 19. SC-Victory｜全 12 关完成 / 真正第一关开始

- **场景地点**：承接第 12 关的顶层战情室，但整面落地窗像大门一样打开，发布路线延伸到清晨城市；室外不是豪华成功庆典，而是刚开始营业的普通街道。
- **叙事目标**：给出完整通关的情绪回报，同时忠于题库结论：办理流程结束，经营才开始。胜利应是“终于可以出门干活”，不是暴富幻觉。
- **镜头与构图**：先保留第 12 关肩平镜头，再缓慢拉成大全景。主角位于中央偏左，打开的窗门/出口形成明亮竖框；右侧城市有少量真实行人和第一位远处顾客剪影，天空从深蓝过渡到暖橙。
- **主角动作表情**：发布杆落下后先因用力前倾、短暂喘气；随后站直，右拳只抬到肩高，左手仍抓背包带。表情是疲惫后的释然和谨慎期待，不露夸张大笑。
- **柜员或配角**：前 11 关的柜员不集体登场。夜班运营员与客服从后方走到窗边，一名远处普通顾客停下看向亮起的店面；人物都保持克制，不抛主角、不跪拜。
- **前景 / 中景 / 后景道具**：前景为已拉到底的发布杆和散开的无字材料；中景为主角、运营员、客服和打开的出口；后景为晨光城市、少量亮窗、刚抬起的店铺卷帘和延伸出去的路线灯。
- **4 个时间节拍**：`T0 0–350ms` 承接第 12 关 Accept，发布杆到底，室内路线全亮一瞬；`T1 350–850ms` 落地窗门向两侧开启，晨光切入，主角被逆光勾边；`T2 850–1450ms` 主角站直并把拳抬到肩高，远处第一位顾客剪影停步，运营员和客服走近；`T3 1450–2200ms` 镜头拉成大全景，主角放下拳迈向出口，城市只亮起少量真实灯点，形成最终成绩页静帧。
- **可复用层**：第 12 关战情室底层、主角 `recover-raise-fist-walk`、运营员和客服、路线灯；晨光、开门和远处顾客必须作为独立层。

## 20. 生图 worker 交付合同

### 20.1 单个场景任务的固定输入

每个 worker 只负责一个场景或一条动作，不跨场景扩张。输入必须包含：

1. 已批准人物母版：正面、3/4 右、右侧、背面、3/4 左、左侧。
2. 已批准表情/动作参照，以及人物母版文件哈希或批准记录。
3. 本文件对应场景的完整条目，不删减 4 个节拍。
4. 3:2 空白布局引导图：标出主角锚点、配角锚点、进度遮挡区和裁切安全区；引导线不得出现在生成结果。
5. 上一张已经批准的场景，仅作为像素密度、描边、调色和光源连续性依据；不得复制其建筑布局。

### 20.2 单个场景任务的固定输出

- 一张 4 格连贯关键帧板，四格均为同一人物身份、同一场景、同一镜头轴线，只推进动作和局部机械状态。
- 一张桌面 3:2 分层母图，以及一张手机同构重排母图；手机图不是桌面图的自动裁切。
- 独立导出的 `BG / MID / FG / NPC / HERO / FX`，透明层不带阴影底色或相邻层残片。
- 一句逐帧 QA：说明每帧的主角发型、背包连接、脚底基线、动作语义和关键道具是否一致。
- 禁止输出 Markdown 图片预览或 base64 到主线程；worker 只返回选中产物路径和简短 QA 结论，由上层统一查看联系表。

### 20.3 硬性拒收条件

- 主角发型、服装、脸型、肤色、背包结构、背包侧袋或肩带连接点漂移。
- 不同帧人物忽大忽小、脚底基线跳动、手脚数量错误、配角与主角粘成一个连通轮廓。
- 12 关只有柜台颜色或纸堆数量不同，缺少本文件定义的独立建筑结构和核心装置。
- 关键帧顺序无法读出明确动作，或第 4 帧离开上下文后无法独立解释当前状态。
- 人物层包含场景、文字、地面阴影、光晕、速度线或其他可分离 FX；场景层包含 UI 或可读文字。
- 手机版裁掉主角头、拳、脚、背包或本关唯一核心装置；桌面版关键交互点落进左上进度覆盖区。
- Accept 在决定之前提前完成支付、放行、启动或发布；Quit 像死亡；Spectate 又让主角回到柜台承担者位置；Victory 制造暴富或大规模虚假用户。

## 21. 最终联系表与验收顺序

最终人工验收按以下顺序进行，前一项未通过不得进入后一项：

1. **人物联系表**：默认立姿、六转面、八表情、所有通用动作；先看身份，再看像素精度。
2. **动作预览**：逐条播放进入、犹豫、阅读、交钱、受冲击、退出、起身围观、终局胜利；检查基线、尺寸和节奏。
3. **12 关场景联系表**：每关只显示 T3 静帧，先验证即使没有文字也能区分地点与叙事。
4. **完整 4 帧分镜表**：逐关查看 T0→T3，检查动作连续性和装置状态是否越权提前完成。
5. **路由联系表**：同一关并排显示 `question / accept / quit / spectate`，确认状态含义互不混淆。
6. **双端裁切表**：桌面与手机同场景并排，叠加安全区和真实 UI 占位框；检查头、背包、手、脚、交互点与核心装置。
7. **浏览器实机**：接入运行时后，在真实桌面与手机视口走完 12 关、每个退出点和围观路径，最后验证减少动画模式直接落到正确 T3。

完成标准不是“有 12 张图”，而是：同一个获批主角以连续、可读、身份不漂移的动作穿过 12 个真正不同的场景，并且所有决策分支都有与状态语义匹配的完整分镜。
